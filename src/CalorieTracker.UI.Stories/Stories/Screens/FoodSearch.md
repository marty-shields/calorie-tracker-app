# Food search

Top-level screen, reached from the **Foods** item of the navigation bar (route `/foods`). View: `FoodSearchView`; page: `FoodSearchPage`. Two routes add a food to the diary and both end at the Serving screen: the Foods tab (a food's values gain **Add to diary**) and a meal's + (add mode, below).

| Part | Content |
|---|---|
| Top bar | Title "Search foods". No back arrow, except while a food's values show. |
| Navigation bar | `BottomNav` with Foods current. A snackbar posted by the Serving screen shows above it (`<Snackbar />` in the `Status` slot). |
| Toolbar | Same layout as Exercises in the workout log app: the search box with the search `Icon` and "Search foods", pinned under the top bar with a line under it; the rows scroll beneath. Hidden while a food's values or the load error show. Results update on every keystroke; a newer keystroke cancels the search still running. |
| Type chips | `FilterChips` under the search box, in the toolbar: Ingredients, Foods, Drinks, All, one chosen. The screen opens on Ingredients every time; a tap changes the filter and repeats the search, and the filter and the text stay while the food list loads. Same wrapping chips as Exercises in the workout log app. |
| Loading | On the first launch the food list is still being loaded in the background: the search box shows and a spinner with "Loading foods…" replaces the results. What is typed meanwhile is kept and searched once loading finishes. If loading fails the screen shows "Couldn't search foods" and Try again, which loads again. |
| Nothing typed | "Search for a food" with the hint "Type a name, like oats or cheddar." |
| Rows | One `ListRow` per food: every typed word must match a word of the food, and the best matches come first: a main word (the name before its first bracket, plus the brand) equal to the typed word, then one it starts with, then one letter off (typed words of 4+ letters only), then a word inside the brackets; a match in the last word of the name ranks higher, foods with fewer extra words rank higher, and for a single typed word a plain common food (such as Milk, average) ranks higher. Ties go A to Z. Its name, and muted under it the type first ("Ingredient", "Food" or "Drink"), the brand when there is one, then "N kcal / 100 g" (or "100 ml"), joined by " · ", and a chevron. Optional nutrients and servings out of range never reach the row or the values (the search bounds them like the Serving screen does). Tapping a row shows that food. |
| No results | "No foods match" under the toolbar, also when the chosen type has none (pick All to look wider). In add mode it is an `EmptyState` with the hint "Try another word, or switch to All." when a type is chosen, "Try another word." under All |
| Search failed | "Couldn't search foods" and Try again, which repeats the search. |
| Food selected | Tapping a result replaces the list with the `FoodValues` block: the food's name, brand, "Per 100 g" (or "100 ml"), energy, protein, carbs and fat, plus fibre, sugars, saturates and salt when known. **Add to diary** (primary) and **Back to results** (secondary) are pinned in the screen's bottom bar, above the navigation bar, while the values scroll above them. **Add to diary** opens Serving with a meal suggested from the time of day. **Back to results**, the back arrow and Android back return to the list with the search kept. |
| After Add (Foods tab) | Serving comes back to this search with the query and type chip restored (route `/foods?q=<text>&type=<Ingredient, Food, Drink or All>`), the list showing, and the snackbar "<food> added to <meal>" with **View day**, which opens the Dashboard with the day in the link (`/?date=yyyy-MM-dd`; the Dashboard opens on that day). Back on Serving returns here the same way. |
| Add mode | Route `/foods?meal=<Breakfast, Lunch, Dinner or Snacks>[&date=yyyy-MM-dd]`, which a meal's + opens. Title "Add to Lunch", a back arrow (and Android back) to the Dashboard, no navigation bar. Same search box, chips and rows. Tapping a row opens Serving at once with that meal preset (no values step). After Add the person goes to the Dashboard with the snackbar "<food> added to <meal>" and **Undo**; Back on Serving returns to this search (`back` route). The meal's + on the Dashboard opens it, with the day on the date strip. |

Back: from a food's values, the list; from the list, the Dashboard; in add mode, the Dashboard.
